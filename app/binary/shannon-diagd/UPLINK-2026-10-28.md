# NR uplink metrics, helper 0.4.4

## Recorded evidence

The user reported UL MCS reverting to zero and missing modulation, rank and
BLER. Examined the paired local NSG captures/JSON exports for
`test_10271955_NR_Measurements`, `test_09182104` and `test_09181844`.
No raw packets, subscriber fields or location were saved to the repository.

The previous helper read MCS from the last periodic ID-1 sample, including
unscheduled zeros, and discarded indices above 27. Captures contain positive
UL MCS reports including 28, interleaved with many zeros. The PUSCH records
already used for throughput/RBs also contain modulation, layers and New Data.

## Supported layouts and aggregation

All offsets below are relative to the NR record body after its four-byte ID.
Current ICD 900 `0xF101`, stack 0:

| Record | Shape | Field | Decode |
| --- | ---: | --- | --- |
| ID 1 debug statistics | 52 B | UL MCS | u32 at 44; accept positive values 1..31 |
| ID 11 PUSCH status | 32 B | Carrier | low four bits of u32 at 0, even values map to CC = value/2 |
| ID 11 | 32 B | New Data | bit 1 of u32 at 4; zero denotes retransmission |
| ID 11 | 32 B | Modulation | bits 9..13 of u32 at 4, Qm = 2/4/6/8 |
| ID 11 | 32 B | Layers | bits 25..27 of u32 at 8 |
| ID 11 | 32 B | Transport block bits | u32 at 24, already used for PHY UL throughput |

For positive-TBS PUSCH records in each completed second, publish maximum Qm,
maximum layers and `100 * retransmission_count / data_record_count` as UL BLER.
This is the retransmission-count metric in the checked NSG exports, not a
network-side CRC failure measurement or the byte-weighted metric used by QBM.
No data records means unknown modulation/layers/BLER. Existing throughput and
RB accounting remain unchanged.

MCS retains the latest positive debug report for at most three seconds, and is
shown only while recent UL activity and serving measurements are available.
A zero debug sample cannot overwrite it. This source does not distinguish
an actual MCS-0 transmission from its no-report zero; ambiguous zeros therefore
remain unreported. Modulation comes directly from PUSCH Qm, never an assumed
MCS table. MCS values at an exact exported second can differ because the two
consumers select periodic samples at different instants; exact MCS agreement
with every NSG row is not claimed.

## Rank and power UI

The uplink row displays Rank, accepting only PUSCH layer counts 1 or 2.
Missing, fractional or unsupported values display a dash; they are not clamped
or defaulted to a rank. This does not depend on RRC configuration.

The installed 0.4.3 experiment inferred SISO/SMSL from SRS port configuration
and SMDL from two scheduled layers. The user requested removal of that inference.
Version 0.4.4 removes its cache, APIs, JSON mode field and test; existing RRC
bandwidth and CSI port decoding stay at their committed implementation.
The user subsequently requested retaining the inference for future research.
Its disabled source and test excerpts now live in `experiments/uplink-mode/`,
outside the build, with integration instructions and limitations.

Power bars use QBM's -27..+26 dBm fill scale and color boundaries at
0/10/17/23 dBm, from green through yellow/orange to red. Unknown values retain
an empty gray track. Power decoding itself is unchanged.

## Verification

Native `nr_uplink.c` checks zero-MCS overwrites, index 28, retransmission BLER,
modulation, layers, control-only windows, idle expiry and independent carriers.
The focused uplink executable passed under WSL before its VM stopped starting
with a host resource error. The helper compiled for static ARM64.

The subsequent recorded-input comparisons ran both helper 0.4.2 and 0.4.3 on
the phone using `--records -`, without opening a modem or sending activation.
Selected records were the complete NR RRC stream plus NR IDs 1/11/31/35/44/55.

| Capture | Completed windows | UL data carrier windows | Old MCS 0 replaced by a recent positive report |
| --- | ---: | ---: | ---: |
| `test_10271955_NR_Measurements` | 181 | 136 | 49 |
| `test_09182104` | 360 | 208 | 52 |
| `test_09181844` | 367 | 297 | 122 |

Every populated new modulation/layer/BLER field agreed with the raw-record
formula. The ARM64 output matched all 640 comparable NSG modulation readings,
640 layer readings and 639 BLER readings, with no mismatches. Existing fields
other than the intended UL MCS/modulation/BLER changes were identical across
all 908 windows, including CSI ports, bandwidth, signals, rates and RBs.
These 0.4.3 capture comparisons establish the PUSCH layer field used for Rank.
The removed mode experiment had produced 464 SMDL and one SMSL carrier window;
those inferred labels are no longer emitted in 0.4.4.

Focused Kotlin snapshot and power-scale tests passed, and the isolated
`assembleDiagTest` APK built successfully. No broad regression suite or
agent-initiated traffic test was run. The source version and app handshake
are both 0.4.4; generated ASN.1 sources and broker behavior are unchanged.
The focused Kotlin snapshot tests also reject any uplink rank outside 1 or 2.
